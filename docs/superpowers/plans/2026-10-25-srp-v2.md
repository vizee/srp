# srp v2.0 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [x]`) syntax for tracking.

**Goal:** 从零开发零配置文件的 expose/relay TCP 反向代理，完成多服务轮询、按需监听、认证加密、防重放、一次性数据 ID 与半关闭。

**Architecture:** 根目录仅保留新 CLI 入口；实现拆分为 options、protocol、transport、relay、expose 五个 internal 包。每个控制会话拥有其请求及数据连接，关闭时全部回收；每个服务由一个协程独占 listener/ticker 局部状态。协议使用 AES-CTR + HMAC 首包、时间与全局 nonce 查重、随机挑战及双向 AES-GCM 流。

**Tech Stack:** Go 1.24+，仅标准库；使用 `crypto/hkdf`，不手写 HKDF。当前验证工具链为 Go 1.27.0。

**Spec:** `docs/superpowers/specs/2026-10-24-srp-v2-design.md`

## Global Constraints

- 完全重新开发；不继承 v1 命令、线协议、内部 API、源码或测试实现。
- 运行模式为 expose、relay；参数按设计文档；默认密钥 `$HOME/.config/srp/default.key`，原始 16/24/32 字节。
- 不读写运行配置文件，无外部依赖；不自动生成密钥。
- 首包 IV 16 字节、random/nonce 24 字节、HMAC-SHA256 32 字节；不包含 CRC32。整数统一大端。
- 时间差严格小于 10 秒，领先/落后达到 10 秒拒绝；全局 nonce 原子查重，固定保留 20 秒，连接关闭不删除。
- 控制 heartbeat 5 秒，7 秒超时；业务消息不能代替 heartbeat。
- listener 管理变量只存在于管理协程函数内；失败每 1 秒重试，成功/停止清理 ticker 并置 nil；注册不依赖监听成功。
- 每服务独立轮询；已释放、未知、重复认领 ID 拒绝；不增加 cancel 消息。
- TCP 建连失败可重试；完整首包发送成功后，同一数据 ID 永不重试。
- 控制关闭连同所有所属请求和数据连接一起关闭；进程退出不等待业务排空。
- 支持配对前及配对后的半关闭；单向 EOF 不释放 pending。
- 保留 Git 历史、LICENSE 与设计/计划文档；替换旧应用文件，不执行整个工作目录的无差别删除。

## Implementation Decisions

- Go 1.24 是采用标准库 HKDF 所需的最低版本。使用真实安装的 Go 1.27.0 测试，不宣称验证过其他工具链。
- 首版只提供 expose/relay 和帮助/版本输出；不带回旧 systemd-service。README 可直接给出简短 unit 示例。
- nonce 表容量 65536，已认证新首包到达上限时拒绝，绝不提前驱逐未过期项。并发握手上限 256、relay pending 上限 4096、每控制会话 pending/数据拨号上限 256、控制消息队列 256；达到容量时拒绝新任务并记录原因。
- 首包及控制消息 JSON 上限 65536 字节，单个 AES-GCM 记录明文最多 32768 字节；每方向最多 2^32 个记录。
- 单个 TCP 拨号最多 5 秒，控制连接初次拨号最多 10 秒；新 TCP 的认证握手最多 5 秒；open 总预算 10 秒，relay pending 15 秒。数据连接建连重试间隔 1 秒，受 open 总预算及控制 context 约束。
- 以完整首包的实际写出结果界定重试：完整消息写出前连接/写入失败可关闭该 TCP 后重试；写出完成立刻标记 Sent=true。后续失败不重试。每次允许的尝试使用新 IV、nonce 和当前时间。
- 配对前不主动读取来源业务数据，保留在 TCP 接收缓冲区；配对后由转发读取并传播 EOF。已观察到的连接错误及 pending 超时正常清理；不声称可提前区分来源 Close 与 CloseWrite。
- 控制重连使用 1、2、4、8、最高 10 秒退避及少量抖动，稳定 30 秒后复位。每次为独立控制会话，不引入 instance_id/generation。
- 服务事件采用合并唤醒：成员状态变更后发送 svc.event，管理协程读取当前是否有成员，不依赖易乱序的历史 start/stop 命令。listener/ticker/stopped 指针仍全部是管理协程局部变量。

## Review Focus

- 认证失败、畸形长度或慢速首包不能注册服务、消费 ID 或无限占用资源；Task 2/4 测试。
- ready 与新请求并发时，expose 必须先看到 ready；Task 4/6 测试。
- 注册/注销快速交错及端口冲突不能让无成员服务继续重试，也不能让旧 accept 关闭新 listener；Task 4 测试。
- 控制断开与 pending 认领并发不能遗漏连接，包含目标拨号及握手尚在进行；Task 5/6 测试。
- 来源先 CloseWrite、服务端先发 banner、较大双向响应均不得挂起或截断；Task 3/6 测试。

## Task 2: New authenticated protocol and encrypted stream

**Files:** `internal/protocol/{keys,handshake,replay,stream,message}.go` 及测试；`go.mod`。

**Interfaces:**
- `NewKeys(psk []byte) (*Keys, error)`；Keys 隐藏派生密钥。
- `Hello{Version int; Type string; TimestampMS int64; Services []string; ID string}`，JSON 字段分别为 version/type/timestamp_ms/services/id。
- `Message{Type, ID, Service, Code string; Accepted, Ignored []string}`；类型包括 challenge/confirm/ready/error/heartbeat/open/open_error。
- `ClientHandshake(ctx context.Context, raw net.Conn, keys *Keys, hello Hello) (*Stream, error)`；失败返回可 `errors.As` 的 `HandshakeError{Sent bool; Err error}`，成功已发送 confirm，尚待读 ready。
- `ServerHandshake(ctx context.Context, raw net.Conn, keys *Keys, replay *ReplayCache) (*Stream, Hello, error)`；成功已验证 confirm，尚未注册/认领、尚未发 ready。
- `NewReplayCache(limit int) *ReplayCache`；内部原子插入、清理过期项，测试可注入时钟，生产 TTL 固定 20 秒。
- `ReadMessage(io.Reader) (Message, error)`、`WriteMessage(io.Writer, Message) error`；长度 4 字节大端。
- Stream 实现 net.Conn 与 `CloseWrite() error`；内部独立方向密钥、计数 nonce、32 KiB 记录与认证 EOF。

- [x] 编写首包布局/完整 HMAC 覆盖、错误密钥、篡改、长度超限/截断/短写、时间 ±9999ms 允许及 ±10000ms 拒绝的测试；编写全局 nonce 并发拒重、固定 20 秒、失败不清表和领先 9 秒后重放的测试。
- [x] 编写 AEAD 往返、大记录切分、短写、反射/重放/重排/跨 session 拒绝、截断及认证 EOF、序号上限测试；补充握手 Sent 分界和旧首包+旧 confirm 拒绝测试。

## Plan Self-review

- Spec 的 CLI、协议、nonce、heartbeat、监听、轮询、pending、重试、会话所有权、半关闭、退出与运维分别由 Tasks 1–6 覆盖。

- relay 与 expose 均通过同一 Stream/Message、Tracker/Bridge 接口协作，配置字段只传服务名或各自本地地址，不跨越目标地址的边界。
